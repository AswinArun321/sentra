The Six Phases of Analysis

A closer look at what happens behind the scenes when a repository is imported into SENTRA.

Step 1

Secure GitHub Connection

Users connect their GitHub account using OAuth 2.0 with state verification. SENTRA enforces strict multi-user account isolation: User A never sees User B's repositories, and tokens are stored securely on the server without exposure to client-side storage or URLs.

Step 2

Repository Selection

SENTRA queries the GitHub API using the user's isolated token to display accessible repositories. Developers can review repository metadata, primary languages, and star counts before selecting which project workspace to import.

Step 3

Repository Tree Inspection

Upon import, SENTRA inspects the repository's Git tree. The manifest detector scans for supported files (requirements.txt, package.json, pyproject.toml), filters out ignored vendor directories (node_modules, site-packages), and identifies README and LICENSE files.

Step 4

Automated File Retrieval

Instead of requiring manual uploads, SENTRA automatically retrieves the required manifest files directly through GitHub's API. This enables automatic scanning while still maintaining manual upload support for custom offline files.

Step 5

Multi-Dimensional Analysis

The engine executes targeted inspection modules: dependencies are extracted and queried against OSV.dev for CVEs, licenses are checked against categorization rules, and the README analyzer audits documentation completeness and structure.

Step 6

Risk Assessment & Reporting

Signals are aggregated by the risk engine to compute a 0-100 score and qualitative rating (Low, Medium, High, Critical). Results are immediately visible on the dashboard, with one-click export to standard JSON reports and CycloneDX 1.4 SBOMs.
